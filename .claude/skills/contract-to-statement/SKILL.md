# 계약서 → 거래명세서

계약서 PDF 한 건(또는 여러 건)으로 거래명세서 양식을 채워 `C:\ChaAI\07_auto_doc\거래명세서\`에 xlsx로 저장한다. 추출과 채우기는 번들 스크립트가 하고, 너는 대상·청구 월·빠진 값을 사용자와 정리하는 역할을 맡는다.

- 스크립트: `scripts/extract_contract.py`(PDF → JSON), `scripts/fill_statement.py`(JSON → xlsx)
- 양식 원본: `assets/거래명세서_양식.xlsx`. 이 파일은 수정하지 않는다. 스크립트가 복사본을 만들어 채운다.
- 필요 패키지: `pypdf`, `openpyxl`

## 진행 순서

### 1. 대상 계약서와 청구 월 정하기
- 계약서는 기본적으로 `C:\ChaAI\07_auto_doc\계약서\`에서 찾는다. 파일 이름에 계약번호(`C-2026-001`)와 거래처명이 들어 있으므로, 사용자가 말한 거래처·번호로 고른다. 여러 파일이 맞거나 하나도 없으면 목록을 보여 주고 고르게 한다.
- 청구 월은 요청에 있으면("10월분", "2026-10") 그 값을 쓴다. 없으면 **이번 달**을 쓴다. 발행일은 그 달 말일이다. 간이형 계약서의 '매월 말일 작성' 규칙과 같다.
- 연도 없이 월만 들으면 올해로 본다.

### 2. 추출
작업 파일은 세션 scratchpad(없으면 임시 폴더)에 둔다.
```bash
python <skill>/scripts/extract_contract.py "<계약서.pdf>" --out "<작업폴더>/<계약번호>.json"
```
결과 JSON을 Read 도구로 읽는다. 콘솔이 아니라 파일로 읽어야 한국어가 깨지지 않는다. 확인할 항목은 다음과 같다.
- `supplier`: 공급자 = 계약서의 **"을"**(서비스 제공자). 새봄바이오가 "을"인 계약(C-2026-001 등)도 있으므로, 새봄바이오를 늘 받는 쪽으로 가정하지 않는다.
- `buyer`: 받는 쪽(귀하) = "갑".
- `amount.basis`: `월`(매월 청구)이나 `총`(총액). `installments`가 있으면 분할 지급 계약이다.
- `period`: 계약기간.
- `missing`: 계약서에서 찾지 못한 항목.

### 3. 빠진 값은 작성 전에 묻기
`missing`에 있는 항목은 xlsx를 만들기 **전에** 사용자에게 한 번에 모아서 묻는다. 계약서에 없는 값을 추측해 넣으면 정상 문서처럼 보여 오류를 놓치기 쉽기 때문이다. 사용자 지침도 '작성 전에 물어보기'다.

| missing 키 | 묻는 내용 | 비고 |
|---|---|---|
| `supplier.phone` | 공급자 전화번호 | 모든 계약서에 없다 |
| `supplier.address` | 공급자 주소 | 간이형 계약서에 없다 |
| `account` | 입금 계좌(은행·번호·예금주) | 간이형 계약서에 없다 |
| `item.spec` | 규격 | 없으면 품명만 써도 된다 |
| 그 밖의 키 | 해당 값 | 추출 실패. `evidence`와 원문을 확인한다 |

- 분할 지급 계약인데 차수를 말하지 않았으면 차수도 함께 묻는다. 차수별 금액을 보여 준다.
- 사용자가 "비워 둬"라고 하면 그 키는 `-`로 넘긴다(빈칸 유지).
- 여러 계약을 한꺼번에 만들 때는 계약별로 묶어서 한 번에 묻는다.

### 4. 채우기
```bash
python <skill>/scripts/fill_statement.py "<작업폴더>/<계약번호>.json" --month 2026-10 \
  [--stage 1] --set supplier.phone=02-123-4567 --set "supplier.address=서울시 …" --set account=-
```
- 저장 위치 기본값은 `C:\ChaAI\07_auto_doc\거래명세서\`이다(`--out-dir`로 바꿀 수 있다). 폴더가 없으면 만든다.
- 파일 이름은 `거래명세서_<계약번호>_<공급자>_<YYYY-MM>[_N차].xlsx`이다. 같은 이름이 있으면 덮어쓰지 않고 `_2`, `_3`을 붙인다. 다시 만들어 달라는 요청이면 기존 파일이 있다는 사실을 알린다.
- 종료 코드 2는 필수 값(공급자 상호·사업자번호, 받는 쪽, 금액, 품명)이 비었다는 뜻이다. 출력된 키를 사용자에게 받아 다시 실행한다.
- 분할 계약에서 `--stage`가 없으면 차수 목록과 함께 오류로 멈춘다. 그대로 사용자에게 묻는다.

### 5. 결과 보고
`<계약번호>.result.json`을 읽고 짧게 보고한다.
- 저장 경로
- 품목, 공급가, 부가세(10%), 합계
- `warning`이 있으면 반드시 알린다. 예를 들어 청구 월이 계약기간 밖이면 계약이 끝났거나 연장된 경우일 수 있다.
- `blank`(빈칸으로 남은 항목)

## 양식에 채우는 칸
| 칸 | 값 |
|---|---|
| B4 | 발행일(청구 월 말일) |
| A6 | `<갑>  귀하` |
| H5 / H6 / M6 | 공급자 사업자등록번호 / 상호 / `대표자 (인)` |
| H7 / H8 | 공급자 전화 / 주소 |
| 11행 | A 날짜, B `품명 (YYYY년 M월분) / 규격`, G 단위, H 수량 1, I 단가 |
| B30 | 비고: 계약번호 · 청구 월(또는 차수) |
| A33 | 계좌번호 |

공급가·부가세·합계(K30~K32)와 합계금액(C9 한글 금액, J9)은 양식 수식이 계산한다. 엑셀이 열 때 다시 계산하도록 설정해 두었다. 부가세 포함 계약이면 스크립트가 공급가액(금액÷1.1, 원 단위 반올림)을 단가로 넣는다. 양식의 부가세 수식(`K30*10%`)에는 반올림이 없어서, 공급가가 10원 단위로 떨어지지 않으면 원 단위 아래 소수가 생긴다. 그런 경우 결과 보고 때 알린다.

## 계약서 형식별 참고
- **표준형**(서명란 표와 별첨2 견적서가 있는 계약, 예: C-2026-001·014): 공급자의 사업자번호·대표·주소·계좌, 품명·규격이 대부분 추출된다. 보통 전화번호만 묻는다.
- **간이형**(1~2쪽, 예: C-2026-018·019·022): "을"의 상호·사업자번호·대표자만 있다. 주소·계좌·규격·전화번호를 묻는다.
- 처음 보는 형식이라 핵심 값(금액·공급자)이 비면 JSON의 `evidence`와 원문 텍스트를 확인해 사용자에게 보여 준다. 정규식을 그 자리에서 고쳐 억지로 맞추기보다 값을 사용자에게 확인받는 편이 안전하다.
